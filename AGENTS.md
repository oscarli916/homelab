# AGENTS.md

Flux manages this homelab Kubernetes cluster from `clusters/homelab/`. Changes merged to `main` deploy automatically.

## Guardrails

- Commit credentials only as `SealedSecret` resources, never as plaintext `Secret` data. Sealing requires the cluster's sealed-secrets public key.
- Keep `clusters/homelab/flux-system/gotk-components.yaml` and `gotk-sync.yaml` generated by Flux bootstrap. Do not hand-edit them.
- Preserve existing regular and Tailscale-only ingress exposure unless the task explicitly changes access.

## Manifest changes

1. Read the affected component and its Flux `Kustomization` under `clusters/homelab/flux-system/`. Use its `spec.path`, `dependsOn`, and health checks as the source of truth for reconciliation order.
2. Follow the component's manifest conventions. For Helm-managed services, use `HelmRelease` and `HelmRepository` resources with a pinned chart version.
3. When adding a component, wire it into reconciliation using the applicable path below.
4. Complete the validation checks before reporting the change as ready.

### Adding an app

Create `clusters/homelab/apps/<name>/` with manifests and a `kustomization.yaml`, then register it in `clusters/homelab/apps/kustomization.yaml`. The existing `apps` Flux Kustomization reconciles that root. Add a separate Flux Kustomization only when the app needs an independent reconciliation boundary or dependencies.

### Adding infrastructure

Create the component under `clusters/homelab/infrastructure/` and add a `*-kustomization.yaml` in `clusters/homelab/flux-system/` pointing to it. Match a neighboring component's layout; some existing infrastructure directories rely on Flux's generated Kustomize configuration rather than a checked-in `kustomization.yaml`.

Declare prerequisites in `dependsOn`. SealedSecret consumers need sealed-secrets ready; custom resources need their CRDs installed first. Preserve existing readiness checks when changing dependencies.

## Validation

- For changed Kustomize roots, run `kustomize build <path>` or `kubectl kustomize <path>`. For directories without a checked-in root, use Flux's build workflow rather than assuming a standalone Kustomize build works.
- For recovery-backup script changes, run `sh tests/backup-recovery-keys.sh`. The test substitutes a fixture for `kubectl` and requires `age`, `age-keygen`, and `jq`.
- Run `git diff --check`. Report which checks ran and any unavailable tools.
- A local build does not prove deployment health. When cluster access is available, check the affected Flux Kustomization and HelmRelease readiness after reconciliation. Otherwise, state that live validation remains unverified.

## Recovery work

Read [docs/recovery-keys.md](docs/recovery-keys.md) before backing up or restoring recovery keys, or changing the backup script or runbook. It defines off-cluster storage, secret-handling constraints, and restore order.
